版本：VV_VIDEO_CONE_V4。基于你上一版 vv 八邻域左探源码继续修改。

交付：vv.zip 与独立 image_params.txt 在同一交付目录。ZIP 不包含参数或龙芯预编译二进制。使用本次参数，复制到解压后的 vv 工程根目录。build.sh 仍删除旧 build、重建编译、移动 vv 到工程根目录、成功后删除 build。

```sh
cd /home/root/smartcar/vv
bash build.sh
chmod +x vv vvv
./vv
```

正常启动不录处理视频；改用 `./vvv` 自动录像，不要同时启动两个程序。vvv 是启动脚本，调用同一 vv 二进制的 --record-processed 模式，共用参数和算法。也支持将二进制重命名为 vvv 后直接运行。只有源码变化需重编译，普通视觉参数约500ms热加载，录像帧率/队列在下次启动读取。

录像实际来源

在 getImageHandle 中，摄像头只取一次帧，NewTrack::processFrame 只执行一次。最终任务处理、转向误差与目标速度确定后，才将当帧内部数据绘制成960x800四宫格，再异步编码。绘制不会修改检测输入、边界数组或转向结果。不需要打开网页/图像显示开关；./vvv 独立开启。

四格依次为：摄像头实际处理裁剪灰度图；原始二值（没有填掉中心黑线）；同帧闭运算图的最大白色8连通域对照；实际闭运算输入上叠加最终左界绿色、右界蓝色、几何中线青色、已检测中心黑线及拐点。最大连通域这格只是对照，普通巡线仍用原7.25轮廓+FixLine，不把对照图冒充实际唯一巡线输入。中心黑线实际参与时画黑色，被环岛/锥桶/发车屏蔽时画黄色并显示 BLACK_USED=0。紫色十字是视觉target_x；steer_error是加入任务偏置后的最终返回误差，二者均来自同一次计算，不代表车辆未来真实轮迹或实测舵机角度。

底部显示 source、视觉target_x、最终steer_error、速度指令、停车指令、门控、五阶段、左探dx/路宽变化/样本行、拐点y、锥桶左右/当前检测/短时保持/通道不足、人行横道远确认/本圈识别/停车、倒Y远确认/近区分叉行、圈数和车库阶段。输入有图但巡线无效时也保存当前画面，明确标记INVALID，不用上一帧成功图冒充。本帧无摄像头输入则没有画面可录。

程序位置 `/home/root/smartcar/vv/vv` 时，每次 ./vvv 单独保存到：

```
/home/root/smartcar/vv/video/run_年月日_时分秒_进程号_毫秒/
  processed.avi
  video_timestamps.csv
  recording_status.txt
```

目录通过/proc/self/exe解析，按二进制位置决定，避免工作目录不一致。视频MJPG/AVI，默认10fps抽帧。CSV每行对应一个已保存的视频帧，包含真实采集时间、任务状态、控制命令以及left_by_y/right_by_y/center_by_y/black_by_y（用分号分隔，-1缺失，索引就是y）。不是另跑一遍算法恢复的估计结果。速度字段是控制目标，非编码器实测速度；环岛complete仅表示状态机视觉完成，不等于外部裁判确认绕满一圈。队列默认4帧，过载丢录像帧，不阻塞巡线；status记录抽帧、丢帧及写盘错误。正常Ctrl+C后先停止控制，再排空录像队列、逐帧解码验证，等CLOSED再断电。强制断电/kill -9无法保证AVI完整。录像启动失败则不发车，错误不会被悄悄当作录像成功。

至少6行的含义

左探开始那一帧保存原始八邻域左边界作为基准。之后每帧比较相同y行：dx=当前left[y]-基准left[y]。仅扫描h/3 <= y < h-3，且两帧坐标都有效。对于h=56，y=18..52，至少round(6*56/60)=6组；这些y无需相邻。比如y=20、24、29、35、41、47各有有效坐标，就是6行，既不是6个拐点，也不是6帧。先取dx中位数，等待180ms排除初始相机变化，然后要求连续3帧达阈值。新版本还对有左右边界的匹配行比较真实路宽right-left变化；左界中位数<=-3且路宽中位数>=2（按80宽折算）才走扩宽入环分支。两边同时向左平移、宽度不变不会仅凭left变小确认。入口已经贴x=0时仍保留“当前入口形状+连续右界+至少6行有效贴边点+连续3帧”的晚门控分支。

环岛策略与适用范围

规则图的第6点是左侧环形岛，且要求绕一圈；它与公众号标准环岛照片的轮廓并不完全一样。因此不能保证必然先看到三个拐点，也不能由3秒时间直接确定入口位置。本版保留五阶段和入口很近时从0直接进入2的处理；普通巡线仍是原轮廓算法，环岛拐点独立采用Moore八邻域（真实邻接像素）。

门控仍是每圈2.9秒后、前14秒内新开候选，至少3个合格内部黑块、纵跨度、倾角22度、纵横比例与连续2帧；识别即限速5。当前有效锥桶候选会阻止新开门控，避免避障区黑块干扰。入口有单侧左断口/上拐点且右边连续时开始左探；没检测到完整入口时，满3000ms后仍须左开口或至少6行贴边左界，并且右边连续，才允许有限左探。纯直道无开口会继续等待，门控失效后恢复巡线。new_track_ring_probe_require_opening=0可回到旧版无条件3秒左探，默认1。

左探最长1100ms；left增大>=3连续3帧按原要求判误检，右偏10持续300ms回正；left减小且路宽增大连续3帧确认入环。未确认则结束本次左探并恢复巡线，不能把缺边(-1)当扩宽。停车/无效找线暂停计时。入环阶段额外左偏最长800ms，阶段3只用几何边界中线，屏蔽中心黑线。状态1补左界直行；2上拐点连右下角补右界并清除远区；3裁顶部三分之一；4右反向出口拐点+双丢线>5补右界；5左中/上拐点相连直行，真实上点消失后完成。整个入环后任务14秒看门狗取消未完成任务，不假报complete。

更可靠的方向是用同机位实车视频标定门控/开口/宽度阈值，再将编码器行驶距离作为入口距离约束，IMU累计航向变化作为绕行进度约束，视觉出口为最终出环条件。相比固定3秒，这些量能更好区分“确实绕了一圈”与“入口附近误出环”。本次没有把未标定的编码器距离或JY62角度接入比赛控制；现有 --imu-test 可先验证硬件读数。左右边界x变化仍会受车身转向与透视影响，新路宽条件降低风险但不能替代实车验证。

锥桶避障

按规则蓝色实心锥桶检测，不再要求一定分成两个蓝块，不使用蓝挡板兜底。全帧提取HSV蓝色及8连通域，先过滤过大/过宽/不合理形状的组件，再检查大部分像素位于实际道路内部，避免大挡板被道路ROI切小后误检。选择最近的有效候选，相对于当前道路中心判断左右，连续2帧才参与。左锥使用其右外缘+4像素作为左界；右锥使用其左外缘-4像素作为右界；上方从原边界平滑衔接，重新计算中心与目标。锥桶任务高于中心黑线，因此不会刚避让又被中心黑线拉回去。

丢检最多保持160ms，录像held=1会标明；发现对侧新锥时清除旧侧保持，避免三锥交错时沿用错误方向。不绑定固定左右顺序。环岛控制和本圈横道后关闭锥桶干预。安全余量4px、最小剩余通道12px均按80宽缩放，仍需按实车轮迹标定。无法形成足够通道则全段不修改边界，记录blocked=1并暂时停驱动，避免绘制穿过锥体的虚假路线；恢复可行通道后解除该临时停车。

保留上版：第一次出库固定右偏5/400ms；横道每圈状态重置、远近确认和强近区漏远兜底；倒Y须分叉到图像底部30%（y>=70%h），横道停车结束后还等1200ms才计倒Y。车库自动倒车仍由原参数控制，不宣称本次已完成其现场调试。
