## 工程入口与复用范围

- `src/linux_main.cpp`：龙芯 Linux 摄像头、电机、编码器、舵机、IMU 和语音入口。
- `src/core.hpp` / `config.cpp`：统一单位、配置及方向验证。
- `src/vision.cpp`：黑线跟踪、白色道路、蓝色锥桶/圆环/车库候选、斑马线、落杆候选检测。
- `src/mission.cpp`：两圈任务状态机，含圆环整圈约束、停车等待、最后倒车入库。
- `src/imu.cpp`：串口协议解析，支持 WIT 11 字节角度帧或 `YAW,<角度>\n`。
- `src/replay_stream.cpp` / `tools/replay.py`：Windows/Linux 离线回放，直接运行上述 C++ 核心，不另写一份视觉算法。
- `tests/core_tests.cpp`：合成图像和任务状态机回归测试。
- `src/hardware.hpp` / `hardware.cpp`：出厂设备协议、PWM/舵机转换、编码器计数和 IIO 航向校准。
- `src/hardware_linux.hpp` / `hardware_linux.cpp`：Linux 完整读写检查、硬件互斥锁、串口 IMU、I2C 语音及设备检查。
- `config/hardware.ini`：设备路径、物理方向、舵机脉宽、IMU 后端和板载输入配置。
- `tests/hardware_tests.cpp`：模拟设备的协议、换向、失败停车和计数/航向转换测试。
- `legacy/`：旧工程源码参考副本。当前只编译与硬件无关的 PID.c，不再编译旧 GPIO/PWM/寄存器/电机/舵机驱动。

新任务流程：出库 → 黑线巡航 → 锥桶绕行 → 圆环入口/环内/出口 → 黑线 S 弯 → 斑马线接近/等待/通过 → 车库旁完成一圈。第一圈继续，第二圈转入对准车库外向轴线、前进留出倒车空间、停车、低速倒车、结束。

硬件层已按提供的 `3.出厂源码` 切换到 LS2K0300 逐飞设备节点；上层继续使用 m/s、米、秒、角度，双轮速度 PID 继续使用 RPS。PWM 会从原控制量范围转换到设备提供的 duty_max。新方向和舵机脉宽取自出厂例程，仍须实车标定。详细迁移说明见 `HARDWARE_ADAPTATION.md`。

## 目前做到什么，尚未确认什么

代码已实现完整任务分支和安全停车路径，但赛道俯视示意图不能代替车载摄像头画面。目前没有实际摄像头安装角、曝光、车辆尺寸、圆环入口实拍、落杆抬起/落下样本、车库实拍及 IMU 型号，默认阈值和几何距离仅是低速调试起点。

具体边界：

1. 普通黑线按逐行窄黑段、连续方向和上一帧位置选择。局部搜索失败后，从近端道路中重新寻找唯一、两侧有白路的黑段，并按 `confirm_frames` 连续确认；多分支或道路边界候选不直接接管。分叉不做地图定位，长时间丢线后的任务故障仍需重新启动。出库初段仍要求摄像头能看到出口引导线，若起始姿态看不到线，应先实拍后补起始车库引导。
2. 锥桶按蓝色、面积、形状和白色地面区分背景，一次优先处理最近障碍并保持绕行侧。同一蓝色区域满足圆环岛规则时不再重复计为锥桶，但接近阶段仍保留其避让间距；同画面中的独立锥桶继续检测。颜色/形状规则仍可能误分类较大锥桶，需实拍校准。没有可靠安全路径就停车。当前采用图像坐标间距，不等同于已验证车体净空，必须实车标定。
3. 圆环按白色道路中的蓝色封闭岛识别；环内择路、转向偏置、方向性累计 yaw、里程与重新发现黑线共同约束出环。若岛在镜头里一直与蓝色背景连通或被裁剪，入口候选可能识别不到；不能宣称任何圆环摆法都适用。
4. 斑马线检测多条黑段；用近端像素行标定停车位置。落杆检测是宽范围彩色/暗色候选，不是行人神经网络分类；杆已抬起但彩色图片仍留在 ROI 内时可能持续等待，普通彩色干扰也可能误停。需要成对实拍抬杆/落杆画面校准 ROI 或更换专用检测器。
5. 停车计时从编码器速度足够低开始，默认 3.3 秒；落杆仍在或可见性未知就不放行。配置 `stop_every_cross` 应按裁判对规则的解释设置：0 为有杆时停，1 为每次都停。没有把“没检测到杆”无条件等同于通行。
6. 入库使用蓝墙候选、IMU 航向和已标定里程。`Complete` 只表示预设倒车动作结束，**不是摄像头已经证明全车入框**。后视摄像头/后向测距未提供，最后一段缺少后向闭环，应低速验证，不能保证入库精度。
7. 编码器改为读取 `/dev/zf_encoder_1/2` 的 16 位计数，按真实采样间隔换算 RPS，并从计数直接计算里程。出厂例程按每次读取的增量使用，默认 `encoder_mode=delta`；附件未含内核驱动，必须上板核实是否读后清零。若实际是累积计数，则选择 `cumulative16` 并验证回绕。还需测每车轮一圈的真实计数、静止读数和采样期间是否溢出。

## Windows 编译与测试

终端进入本工程：

```powershell
cd 'C:\Users\巩钰\Desktop\2026龙芯\SMART_CAR_2026'
.\build_windows.ps1
```

脚本优先查找 `tools/zig-windows-x86_64-0.13.0/zig.exe`，随后查找本次实际安装的 `tools/python_compiler/ziglang/zig.exe`，也可传 `-Compiler 'D:\tools\g++.exe'`。输出 `build/core_tests.exe` 和 `build/vision_stream.exe`；这些是 Windows 验证程序，**不是可拷到龙芯运行的车控程序**。`tools/python_compiler`、`tools/validation_headers` 和 `build` 仅用于本机验证，板上部署不需要这些目录。

回放实拍图像、图像目录或录像：

```powershell
python -m pip install opencv-python
python tools/replay.py camera.avi --stage Cones --preview --output cones.jsonl
python tools/replay.py race.avi --telemetry race.csv --output race.jsonl
```

没有 CSV 时只检测画面，**不假造里程或航向推进比赛任务**。`--stage` 可选 Depart、Cones、ToRing、RingLap、CrossWait、ToGarage 等状态；带 CSV 时从起点完整回放，忽略感知阶段选项。CSV 必须与录像逐帧对应，yaw 已解绕，distance 是前进和倒车均递增的累计行驶距离，不是带符号位置。必需列：

```csv
time,distance,speed,yaw,yaw_valid,yaw_measured
0.00,0.000,0.000,0.0,1,1
0.05,0.005,0.100,0.2,1,1
```

JSONL 含状态、圈数、速度、转角、路径置信度和元素识别结果。回放不会访问 GPIO 或电机。已有输出文件会覆盖，请使用新的输出文件名。

实车 CSV、Python → C++ 遥测传输和 JSONL 时间戳使用 17 位有效数字，保留大时间基数下的逐帧时间间隔；处理尺寸在回放启动时读取一次，与 C++ 配置保持一致。

## 龙芯 Linux 构建和运行

目标板需具备 CMake、C/C++ 编译器、OpenCV 开发头文件/库、出厂逐飞设备节点及配置的 IIO/串口/I2C 接口。当前运行程序不依赖旧 sysfs PWM/GPIO 或 `/dev/mem`。建议先在板上原生构建；Windows 测试不证明目标板依赖已经满足。

```bash
cd SMART_CAR_2026
bash build_linux.sh
# 检查设备协议和当前读数，不写电机/舵机输出（会消费增量编码器计数）：
sudo ./build-linux/SMART_CAR_2026 --hardware-check
# 只看摄像头，完全不初始化电机/编码器/舵机：
./build-linux/SMART_CAR_2026 --preview
# 只看录像：
./build-linux/SMART_CAR_2026 --video sample.avi --preview
```

如需交叉编译，使用 `cmake/loongarch64.cmake` 并提供真实工具链目录、目标板 sysroot 和 **龙芯版本 OpenCV**；不能拿 Windows/x86 OpenCV 链接，也不应直接部署 Windows exe。

完成下述标定、确认机械急停可用后，才将 `motion_calibrated=1`。默认使用 IIO IMU；若缺少驱动 scale 节点，先在 `hardware.ini` 填入已核实的比例系数。使用串口 IMU 则选 `imu_backend=serial`，填写 `imu_serial_device`（旧 `competition.ini` 的非空 `imu_device` 会覆盖它），再运行：

```bash
sudo ./build-linux/SMART_CAR_2026 --drive --config config/competition.ini --record race.avi --telemetry race.csv
```

默认不加 `--preview`，减少显示耗时。两份记录每帧顺序一致；AVI 固定 20fps 仅用于播放，任务回放时间以 CSV 为准。视觉命令超时默认 0.4 秒由独立电机线程置零；路径长期丢失、编码器异常、卡住、错误速度方向、任务超时或 IMU 中断会锁定故障，需要退出后重新定位再启动。Ctrl+C 正常路径会停车；断电、内核故障、SIGKILL 等不能靠用户态析构保障停车，仍须物理急停或硬件看门狗。

硬件初始化及 IMU 等待结束后会重新读取摄像头，再计算第一条行驶命令，避免复用初始化前的画面。这不等同于已验证摄像头驱动内部缓存的新鲜度，目标板仍需实测。

## 按顺序标定，不要直接跑两圈

1. **架空轮子，先检查新接口**：路径集中在 `config/hardware.ini`。默认左右电机分别 motor_1/2，正转方向高电平；左编码器取反，右编码器保持。检查物理左右及正反转，不用编码器符号掩盖电机反转。出厂接口未给出独立总使能节点，本程序不会继续写旧 GPIO73。
2. **速度和静止**：手动确认正转 RPS 符号、每车轮一圈实际脉冲数、轮周长；停车时读取值必须可靠归零。两个编码器符号分别配置，前进测量应正、后退应负。验证实际距离与累计 distance，不可靠就不能用于圆环/停车。
3. **舵机**：先运行 `sudo ./build-linux/hardware_servo_test`，检查脉宽中位及限位。默认中位 1490us，`steer_offset_deg` 已由旧 -15 改为 0；这是消除旧标定在新中位上的叠加，实际直行仍须测量。正 steer 指右转、负指左转，`servo_reference_deg` 仅为初始换算参考。检查 `steer_sign`、机械限位和 servo→车轮比例。PID 仍需在真实采样周期下重新调。
4. **IMU**：默认 IIO，支持出厂 IMU660RA/660RB/963RA 原始陀螺仪。保持整车静止约 2 秒完成零偏校准；缺比例系数、轮子移动、波动过大或采样中断会失败停车。积分航向为相对角度，仍有漂移；确认安装轴、符号、绕行整圈误差。可切换串口 WIT11/ASCII 后端，确认设备、波特率和协议。`require_imu=0` 仅用于台架；若不使用 IMU，应同时显式设 `imu_backend=none`。
5. **视觉**：固定镜头位置、焦距和曝光，拍摄直线/弯线、三个锥桶、圆环入口/中段/出口、S 弯、两种杆状态及车库；用回放查看红色黑线路径、绿色白路路径、识别误报。颜色阈值集中在 INI，完整合法参数见 `src/core.hpp`。
6. **单元素低速**：从起点实际顺序测试。入口漏识别、绕行路径越界、圆环转向错误、出口黑线提前可见、条纹遮挡黑线等分别核对。圆环必须实测选择 `ring_side`，同时修正 IMU 符号。
7. **斑马线**：测近端条纹所在行与前保险杠位置，标定 `cross_stop_y_ratio`；确认完全停住后计时和杆抬起才走。不能把示意图位置比值当真实停车距离。
8. **入库**：在人工保护下测车库检测点、车库向外轴线相对航向 `garage_outward_yaw_delta_deg`、对准距离、前进留空距离、倒车距离；确认整个车体入库且不碰蓝板。默认 -30° 和各距离不是按图精确算出的数值。
9. **整圈**：先完整一圈观察阶段日志，再两圈；只有稳定重复通过之后再逐项提速。安全故障不是自动恢复授权，不要在错误位置清故障后继续。

## 修改后的五项检查

- 重复代码：车上与离线回放共享 `car_core`；左右电机共用协议/换向方法，舵机测试共用同一脉宽转换，旧驱动只归档。
- 命名：统一 Stage/Observation/Telemetry/Command；参数名称标出 `_m`、`_s`、`_deg`、`_ratio`，旧驱动拼写保留兼容。
- 结构：感知不直接操控电机；状态机决定目标；独立控制线程闭环和看门狗；默认只感知。
- 隐藏问题：覆盖原任务回归及新硬件模拟测试，包括部分初始化失败、完整读写、PWM 单位、换向前清零、双轮停车、计数回绕、静止速度、IIO 校准/断流。目标板实际行为仍待验证。
- 优化方向：实拍标定优先，其次可靠编码器计数里程、道路透视/车体净空建模、杆状态专用分类、入库后视闭环；最后才提速。当前不虚构这些硬件或训练模型已经存在。
