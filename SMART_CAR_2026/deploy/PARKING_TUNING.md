# 六阶段手推入库调参

本工具按用户授权设置舵机，由人手推/后拉；相机录像并读取编码器、前后超声波等已配置输入。没有电机、GPIO输出或IMU初始化，不执行图像建议，不自动确认入库成功。已有几何规划独立保留；此次是实车手动复现和找参数的入口，不要求补测量角。

## 只改这一个文件

板上 `/home/root/gy/deploy/config/parking_tuning.ini`；源码模板 `deploy/config/parking_tuning.ini`。终端不接受角度数值。文件提供六组相同字段，修改角度或保持时间时只改对应阶段。

| 字段 | 作用 |
|---|---|
| `[session] mode=single` | 只调一个阶段；完成后再次测试同一段，不自动进入下一段 |
| `[session] mode=full` | 按顺序预览下一段；仍须每段授权，六段完成也不自动停止记录 |
| `[session] stage=2` | 直接从第二阶段开始；改为1可从头走完整流程；R加载时也用它选择新阶段 |
| `steer_command=-10` | 舵机命令；负数左打，正数右打。范围±15且受车辆配置上限限制；不是实测前轮角度 |
| `settle_time_s=0.5` | 第一次Enter设置舵机后，保持静止等待至少0.5秒；范围0.5～5秒 |
| `hold_time_s=5` | **第二次Enter允许推车时**开始保持计时，5秒到后自动回正；范围0～120秒，0关闭定时回正 |

默认只进入第二段：第一倒弯-10/保持5秒；第四段+10/保持5秒；其余命令0/保持时间0。±10与5秒只是便于初试的参数，不是最优值。36.7°是线路几何夹角，不能直接填成舵机命令。

## 操作流程

1. 把小车摆到所选阶段的起始位置，保持静止，运行 `sh /home/root/gy/deploy/run_parking_rehearsal.sh`。启动就持续采集，每秒打印阶段名称和等待事项；没有自动结束时间，启动不写舵机。
2. **第一次Enter**：声明车身已停稳，授权设置本段角度。看到`WAIT_SERVO_SETTLE`保持静止；达到`settle_time_s`后显示`WAIT_PUSH_PERMISSION`。此时保持计时尚未开始。
3. **第二次Enter**：授权开始这一段手推/后拉，同时启动`hold_time_s`。按车轮自然滚动，不横向掰动车身。第六段是静态停止确认，保持车身静止。
4. 保持时间到：后台写入配置零位，显示“时间到，舵机已自动回正”；记录继续、当前阶段不变，不替你停止手动推动。屏幕显示最近软件写入命令、保持剩余时间及超声波原始读数。
5. 实际停稳后，再按Enter结束当前试次。录像和读数仍继续。在`full`模式下一次Enter才设置下一段舵机，之后仍需等待并再次Enter才能推车；`single`模式再次授权则重复当前段。第六段结束后停留在第六段，不自动退出。
6. **P再Enter**：暂停实验录像和传感器记录。舵机不因P立即改变；已经启动的保持计时继续，到时仍自动回正。不要在暂停记录时开展新的运动试验。
7. 暂停后编辑文件；**R再Enter**只校验并显示候选参数；**C再Enter**只恢复记录。恢复后第一次Enter才应用新文件、选择其中的stage并写舵机；等待后第二次Enter才开始新的试次。R校验失败保留原参数；C不会自行执行R预览的配置。
8. 完成后实际停稳，**Q再Enter**结束、写入配置零位并保存。Ctrl+C同样执行退出回零。程序没有电机停车能力；Enter/P/Q仅是人的停稳声明，不是传感器已经证明物理静止。

所有字母键后都要按Enter。不支持直接输入数字；一次收到多行回车会拒绝授权。等待期间输入的回车不会被留到下一状态自动执行。系统/设备阻塞仍可能延迟屏幕更新、按键处理和退出；独立舵机线程仅保证回正任务不依赖摄像头循环，不保证操作系统与硬件驱动的实时性。

## 六段各做什么

| 阶段 | 人工动作和结束判断 |
|---|---|
| 1 前移 | 名义回正，沿主线前推到准备起倒的位置；交点/起倒距离由你此次复现判断 |
| 2 第一倒弯 | 初试左打-10后拉，车尾倒向斜分支；角度保持时间到会自动回正 |
| 3 分支直退 | 车身接近分支方向后，沿分支直退到准备接入库轴的位置 |
| 4 第二倒弯 | 初试右打+10后拉，使车身接入与主线平行的库轴；按实际结果分别调角度和保持时间 |
| 5 库内直退 | 回正后倒向终点，人工观察车体位置、前相机可见虚线和有效后挡板距离 |
| 6 停止确认 | 保持静止采集终点图像及测距，人工确认；最终仍用P暂停或Q结束 |

计时控制只能保证保持命令的时间。手推速度不同会改变这一段走过的距离和转过的角度，所以比较参数时尽量保持接近的推动速度，先只改一个参数。

## 每次启动的数据

独立会话目录在 `/home/root/gy/deploy/captures/parking_tuning/rehearsal_.../`，不会覆盖上一次。固定创建这六份CSV：

```text
01_advance.csv
02_reverse_first.csv
03_reverse_branch.csv
04_reverse_second.csv
05_reverse_straight.csv
06_stop_confirmation.csv
```

未进入阶段只有表头，不伪造数据；重复测试同一阶段追加到同一CSV，用该阶段的`trial`区分试次；编号在允许推动时才增加，此前准备状态仍显示上一编号（首次为0）。数据包括按键、阶段状态、实际配置版本、配置命令与最近软件写入命令、相机读帧区间、逐通道原始数值/单位/有效性/系统调用返回值、舵机写入、保持计时开始和定时回正事件。`AUTO_CENTER`只表示软件零位写入成功；`AUTO_CENTER_FAILED`是回正失败，不证明机械转角。

`config_1.ini`及后续版本保存当次实际应用的调参文件；传感器、车辆和硬件配置也保存副本。`camera_1.avi`等是共用录像，每1800帧换新片段，换片不停止记录；CSV的`clip/video_frame`用于定位画面，控制事件可引用最近已记录画面。视频标称FPS不代表真实时间：暂停间隔和实际帧时间必须看CSV单调时钟。编码器原始读数未换算里程/车身朝向，超声波原始值未自动换算厘米。

传感器在每次正常记录帧后读取一次，实际频率随相机/设备耗时变化；此工具不采用旧采集器的20ms后台采样。暂停期间不写实验样本、不读取传感器，相机仍取帧维持数据新鲜。暂停时发生的定时回正事件先保存在内存，C恢复或Q收尾时写回对应阶段CSV，保留实际发生时间；延迟补写的事件需按单调时钟排序，不能仅按CSV行号判断顺序。这不恢复暂停期间的录像或读数。Q后的文件关闭/fsync、配置/会话摘要是保存步骤。

缺少允许省略的灰度通道会标记`UNCONFIGURED`，正常保存后的退出码为2；这是部分采集，不能算全部传感器有效。相机、终端、存储或舵机失败会报错、尝试回零并保存可用记录；不会报告自动入库成功。

## 编译一次，再用一条命令启动

本次提供源码、脚本、参数文件和打包检查；本机未生成或执行新的LoongArch二进制。不能把Windows测试exe当板上程序。共享目录同步好后，在已有龙芯构建虚拟机运行：

```sh
cd /mnt/hgfs/share/SMART_CAR_2026
sh deploy/build_parking_rehearsal.sh
```

脚本沿用 `/home/gy/builds/SMART_CAR_2026-loongarch` CMake缓存，编译目标`parking_rehearsal`，打包工具只接受含当前版本和功能标记的64位小端LoongArch ELF。目标OpenCV必须为板上匹配版本；架构、版本或文件格式错误不会生成所谓可部署包。

生成的 `deploy/parking_rehearsal_20261007_1_verified.zip` 上传到板上 `/home/root/gy/deploy/`。已有`manual_capture.ini`、`config/calibration_hardware.ini`与`config/calibration_vehicle.ini`继续使用。板上安装运行：

```sh
cd /home/root/gy/deploy && \
unzip -o parking_rehearsal_20261007_1_verified.zip && \
sha256sum -c PARKING_TUNING_SHA256SUMS && \
chmod +x parking_rehearsal_20261007 && \
sh ./run_parking_rehearsal.sh
```

之后只需：

```sh
sh /home/root/gy/deploy/run_parking_rehearsal.sh
```

安装只在调参文件缺失时复制`parking_tuning.example.ini`，再次解压不会覆盖你修改的参数。脚本检查程序版本并设置既有OpenCV库路径。需要完整流程时，在板上编辑：

```ini
[session]
mode=full
stage=1
```

其余六段字段保留，暂停时R预览、C恢复，再Enter才应用。
