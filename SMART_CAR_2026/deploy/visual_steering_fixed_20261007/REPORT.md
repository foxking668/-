# 前相机参考线修正与五段录像复核

2026-10-07。本轮已修改实际C++视觉源码，并完成离线验证。解决了已复核的暗地面误选、停车参考丢失后全图换线、底部缺线导致搜索中心复位，以及跨行碎片混接问题。当前电机不能使用，本轮没有访问小车硬件，也没有完成实车自动调舵或倒车入库。

## 修改及其目的

1. **局部亮度对比。** 原黑色阈值85会把本批亮度约60～90的地面也纳入黑色区域。新增导引线候选掩膜：候选本身必须够暗、宽度合适，且比左右两侧都明显更暗。新增参数line_local_contrast_min，默认15，允许5～80；已有配置缺少此键时使用默认值，本轮未覆盖车辆配置。原黑、白、蓝掩膜继续供道路、颜色和其他事件识别使用。
2. **停车参考连续性。** 已有可信参考时，停车阶段限制逐行候选相对上一帧的位置；局部丢失后不进行全图替换。仍可恢复附近同一参考；显式resetTracking才允许重新寻找。它是图像连续性约束，不是已完成的主线/分支语义地图。
3. **底部缺线。** 最底部一行太宽或缺失时，从上一帧附近下部的有效行取搜索起点，避免退回图像中心而丢失上方仍可见的线。
4. **歧义与碎片混接。** 两个候选评分接近时输出ambiguous；停车路径出现过大的跨行横向跳变时输出discontinuous。这两类结果confidence归零，不更新可信参考。回放JSON分别增加line_ambiguous和line_discontinuous，便于核对拒绝原因。
5. **无效图像。** 停车时短暂黑屏或无效图像清除新参考的确认计数，保留先前参考，避免恢复画面后无声换线。其他阶段继续原有重置行为；处理高度改变时旧参考不再适用。

本轮没有修改Mission运动状态机或舵机/电机输出。上述拒绝标志表示视觉结果不可信，不等于已经实现实车停推提示、图像超时处理或执行器闭环。

## 按用户要求进行的五项代码检查

1. **重复代码：** 跟踪和重获参考共用guideRuns；亮度数据来自同一次图像预处理，未另建第二套HSV流程；两种无效图像共用rejectFrame。回放继续复用现有协议、时间读取和清理流程。
2. **命名：** guide、brightness、nearReferenceX分别描述候选、亮度及参考种子；ambiguous与discontinuous分别表达多候选和跨行跳变。heading仍是图像特征，报告明确不将它称为实际车身角度；steer_command仍不是已量出的wheel_angle。
3. **结构逻辑：** 原颜色/道路任务使用原掩膜，导引线使用局部对比候选；候选选择、路径测量和质量拒绝分别处理；只有评分达到门槛的参考才写回上一帧。停车丢失参考时保持局部恢复，普通道路保留原重获流程。
4. **隐藏bug：** 实际修复了底行缺失退回中心和无效帧清除停车参考两个问题；增加碎片突跳测试，避免行命中率把混接路径评为可信。扫描端点、左右邻域范围、缺行桥接、相邻候选歧义、时间精度和异常输入已检查。仍不能保证所有未标注场景中的参考身份正确。
5. **优化建议：** 行局部均值使用前缀和，避免每个像素重复遍历整个邻域；当前与原处理分辨率相同。后续优先检查转弯时因线宽/透视及皱褶导致的丢失，结合多行形状和交点关系做参考身份确认；不要直接放宽全部候选或取消拒绝。黑线候选修改也影响普通行驶阶段，完整赛道还需真实录像验证；本轮合成任务回归不能替代它。

## 用户现在需要做的事

这一步不需要重新录像、量角或继续推车，也没有新的板上闭环程序需要上传。现有五段固定档位方向记录保留，最后一段末尾仍在运动可以接受，不用于停稳姿态标定。

下一步是处理转弯段仍丢失的参考，并提供默认不写执行器、只记录参考质量和建议命令的观察模式。只有参考身份、误差定义、前推/后推符号、帧超时和限幅全部核对后，才启用人工推动下的舵机反馈。完整入库还需要库轴/交点定位及独立地面尺度验证；36.7°场地夹角不能作为舵机命令。
