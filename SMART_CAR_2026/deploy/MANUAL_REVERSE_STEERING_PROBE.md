# 倒车舵机响应验证：人工后拉，终端选择小角度命令

当前源码版本为 `2026-10-07.3`。这是显式启用的舵机响应试验，尚未在龙芯板执行新版本，不是自动纠偏或完整倒车入库程序。电机不能使用、没有 IMU 的现状保持不变。先完成下面的一段 `+2` 验证；不重拍已经完成的观察录像，不重新量转角。

## 为什么暂时不能把建议值直接接到舵机

最新版 `.2` 后拉录像已收到：73 帧中，开始阶段拒绝不适合的曲线/混接，随后有 49 帧连续跟踪；参考是在后拉过程中建立的，软件没有舵机或电机写入。它证明了这一段的局部直线观察可以持续，尚未证明闭环方向或车体对正。

观察器里的 `lateral_error_image` 是近处图像线位置相对参考的差，`heading_error_image` 是拟合直线远近两个位置的差相对参考的差。透视投影下，车体横移和转动都会改变这两个值，前相机又位于后轴前约 23cm。因此不能把它们直接当作后轴横向偏差和实际航向，整项反号或只反其中一项都没有经过实际闭环验证。

可独立推导的小角度运动模型为：后轴横向偏差为 e，车头右偏角为 ψ，前进速度为 v（倒车时为负），轴距为 L，实际前轮转角为 δ；则 `e_dot = v*ψ`、`ψ_dot = v*δ/L`。相应的局部稳定反馈可写成 `δ = -ke*e - sign(v)*kψ*ψ`，横向项不随倒车整体反号，方向阻尼项随速度符号改变。测试使用该模型检查收敛和错误整体反号的反例，另用前相机投影检查远近图像差确实同时受 e、ψ 影响。这个模型不是当前未标定图像量到舵机命令的映射，也不是实际转角标定结果。

已有诊断建议值为兼容旧录像保留；新试验绝不采用该建议值。仅 `R`、`+`、`-`、`0` 对应显式请求，命令是配置中的 0、+2、-2，不等于实际前轮角度。

## 本次只做一段 +2 后拉

选上一段已能持续识别的直线区域，把车身大致平行于直线，保持镜头安装不变。初始先实际停稳；不是把前轮轻微左偏另行改成新零位，也不要求把线压在图像正中央。试验参考是当前停稳姿态下的直线图像。

```sh
./manual_capture_probe_20261007 --config manual_capture.ini --hardware-config config/calibration_hardware.ini --vehicle-config config/calibration_vehicle.ini --allow-partial --duration 45 --steering-probe reverse --output captures/manual_reverse_probe_plus2
```

1. 让小车保持静止约 2 秒，输入 `R` 并回车。程序仅在两路编码器连续至少 0.8 秒零增量且样本新鲜时，写配置 0 命令并开始建立直线参考。应看到 `CENTER_THEN_BUILD_REFERENCE ... command=0`。
2. 继续停稳，等 `PROBE_REFERENCE_READY`。这需要连续有效的局部直线帧；没有出现就先不后拉。若出现 `REJECT_REFERENCE_NOT_STATIONARY`，停稳后再次单独输入 `R`；不要把多行控制键一次粘贴进去。
3. 仍停稳，输入 `+` 并回车；等 `PROBE_STEER_READY ... command=2`。这时才开始缓慢向后拉约 20～30cm，让轮胎自然滚动。不要横向扶正或扭动车身。观察的是小角度实际响应，不以保持车身直退为要求。
4. 若出现 `HOLD_STOP_PUSHING`，立即停止后拉。程序保持原命令，待新鲜编码器持续零增量后回 0，并显示 `REST_ZERO_REARM_REQUIRED`；本段到此结束即可，不必在这一段继续重新试验。
5. 正常完成也先停稳约 2 秒，输入 `0` 回车并等 `PROBE_STEER_READY ... command=0`，再输入 `Q` 回车。整个动作在 45 秒内完成；期限不足时直接停稳、结束，不赶时间。
6. 等待 `SERVO_ZERO`、`VERIFIED`、`SAVED` 和 shell 提示符，把整个 `manual_reverse_probe_plus2` 文件夹及终端日志发回。注明车尾大致向左/右/基本直退、是否打滑或横向扶正即可，不需要量角器，也不必量真实轮角。

本轮暂不做 `-2` 或提高命令幅度，先检查这一段响应和日志。程序支持 `-`、`0` 以便后续验证；切换命令均须先实际停稳并等待软件门槛，不能在后拉中连发方向命令。

## 明确的状态和边界

- 默认采集和 `--observe-steering` 仍无执行器写入；`--steer-command`、`--observe-steering`、`--steering-probe` 相互排斥。检查模式不访问硬件。试验要求显式时长 ≤60 秒、delta 编码器模式和配置命令上限至少 2。
- 只有手动 `R` 后、停稳且连续有效直线帧才进入 `READY`；开始录像就移动不能建立本模式参考。`R` 回零后才重新采集参考，不借用此前移动中建立的图像目标。
- 尚未输入有效 `R` 时，`S` 或启动阶段的时钟故障恢复也不初始化舵机；不会把“停止试验”变成隐式输出授权。
- 参考丢失、身份变化、图像误差超过 0.08 的归一化范围、旧帧或编码器失效进入锁定 `HOLD`。图像范围只是试验门槛，不是厘米或实际车角。恢复一条线不会自动恢复输出，停稳回零后需要重新输入 `R`。
- 两路计数分别检查，非零计数不能左右相抵后当成静止。读取失败、非有限值、重复时间、采样间隔异常均不能通过静止门槛；两路读数跨度和样本年龄须 ≤0.25 秒。程序复用唯一采样线程，不再次读取会清零的编码器，不用轮差估算航向。
- 正常命令在硬件元数据读取和日志刷新后、实际写入前再次检查停止状态及图像时效，延迟期间门槛改变便取消写入。已排队的终端控制键合并检查，同批 `Q` 优先退出，多条控制命令拒绝执行，EOF 结束试验。
- `S` 是锁定试验并提示停止后拉，不是刹车。退出、信号、期限到达或采集失败均尝试立即回配置 0；先停推再退出。编码器软件静止不保证物理静止，用户须遵循停稳顺序。摄像头底层阻塞时没有独立舵机看门狗，程序也没有能力让人工推动立即停止。
- 后超声波本次仅记录原值，不做偏斜控制或停车阈值；没有可确认的竖直目标时跳变读数不补充姿态。`motion_calibrated=0` 保持，不开启正式电机驾驶。

## 文件与验证意义

复用 `camera.avi`、`frames.csv`、`sensors.csv`、`markers.csv` 和配置快照。`visual_observer.csv` 保存原图像特征及未执行的诊断建议，`servo_writes` 是截至该帧的成功软件舵机 API 次数。`steering_probe.csv` 保存按键、门槛、状态、请求与上次成功命令，`servo_events.csv` 单独记录每次请求的准备、取消、失败或软件成功，以及退出回零。仅有 `PREPARE` 不能认作成功写入；`SOFTWARE_OK` 也不是实际轮角或物理波形证明。

所有提示均是软件事件；只有程序明确记录写入成功才显示对应准备完成提示，写入失败会结束采集并尝试回零。退出回零优先于事件日志落盘，磁盘失败不能跳过该尝试。原始录像目录保持不变，新增文件写入新会话。

五项审查：共用视觉、舵机、录像和唯一传感器线程；用 probe/command/image 命名区分试验、命令和物理量；纯状态机与输出分离；检查失效锁定、终端批次、时钟、日志/输出失败和退出优先级；优化为一段低幅度有明确目标的试验，再按实际响应决定闭环方案，避免继续无目的地增加档位。

本次验证：148 项核心、75 项观察器、112 项手动舵机/试验状态、368 项模拟硬件、46 项采集数据和 18 项灰度/时间范围检查，共 767 项通过；二进制回放接口与真实图像/视频、时间戳集成检查通过；8 段既有录像共 833 帧回放通过，最新后拉记录保持 49 帧有效，原文件哈希不变。17 个 Linux 编译单元通过，最终修改的采集工具和试验测试再次编译检查通过。这些是 Windows 模拟、离线回放和 x86 Linux 编译检查，没有生成或运行新的 LoongArch/OpenCV4.11 程序，也没有证明实车自动纠偏收敛。
